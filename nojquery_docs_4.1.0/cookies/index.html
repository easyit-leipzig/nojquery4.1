Document Cookies

Cookies

JSON-fähige Cookie-Helfer für das Setzen, Lesen, Prüfen und Entfernen kleiner browserseitiger Werte.

set()get()has()remove()OptionenSicherheit

Grundbeispiel

nj.cookie.set('theme', 'dark', { days: 30, sameSite: 'Lax' });
const theme = nj.cookie.get('theme', 'light');
nj.cookie.remove('theme');

nj.cookie.set(name, value, options)

nj.cookie.set(name, value[, options = {}]) → value

Serialisiert den Wert mit JSON.stringify(), URL-kodiert Namen und Wert und schreibt das Ergebnis in document.cookie.

nj.cookie.set('preferences', { compact: true }, {
  days: 14,
  path: '/',
  sameSite: 'Lax',
  secure: true
});

nj.cookie.get(name, fallback)

nj.cookie.get(name[, fallback = null]) → any

Sucht den Cookie, dekodiert den Wert und versucht anschließend JSON.parse(). Fehlt er, wird der Fallback zurückgegeben.

nj.cookie.has(name)

nj.cookie.has(name) → Boolean

Prüft die Existenz mithilfe eines internen Symbol-Fallbacks. Dadurch werden auch gespeicherte Werte wie null korrekt erkannt.

nj.cookie.remove(name, options)

nj.cookie.remove(name[, options = {}]) → true

Setzt denselben Cookie mit days: -1. Für eine zuverlässige Löschung müssen insbesondere path und gegebenenfalls weitere Attribute zum ursprünglichen Cookie passen.

Unterstützte Optionen

OptionUmsetzung
daysWird als Max-Age = days × 86400 geschrieben.
pathStandard ist /.
sameSiteWird unverändert als SameSite ergänzt.
secureErgänzt bei wahr den Schalter Secure.
Das aktuelle Core-Modul unterstützt keine Optionen für domain, expires, HttpOnly oder Partitioned. HttpOnly kann grundsätzlich nicht durch JavaScript gesetzt werden.

Sicherheit und Grenzen

  • Keine Zugangsdaten oder dauerhaften Geheimnisse in JavaScript-lesbaren Cookies speichern.
  • Secure für HTTPS verwenden.
  • SameSite bewusst festlegen.
  • Browsergrenzen für Anzahl und Größe von Cookies beachten.
  • Cookie-Inhalte sind clientseitig veränderbar und dürfen nicht ungeprüft vertraut werden.
