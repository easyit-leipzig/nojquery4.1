History Router

Routen ohne
Seitenwechsel.

Das Router-Modul verbindet deklarierte Pfadmuster mit Handlern und nutzt die History API für Navigation innerhalb einer clientseitigen Anwendung.

API ansehenTemplates
nj.route("/users/:id", ({ id }) => {
  nj.render("#app", "<h1>User {{id}}</h1>", { id });
});

nj.router.start();
nj.navigate("/users/42");

Überblick

Routen werden mit nj.route(pattern, handler) registriert. nj.router.start() wertet den aktuellen location.pathname aus und reagiert anschließend auf popstate. Navigation erfolgt mit history.pushState() oder history.replaceState().

Wichtig: Der Router arbeitet mit echten Pfaden wie /users/42, nicht mit Hash-Routen. Der Webserver muss deshalb bei direkten Aufrufen solcher Pfade die Anwendung ausliefern.

Routing-Ablauf

  1. Routen mit nj.route() registrieren.
  2. Router einmal mit nj.router.start() starten.
  3. Aktuellen Pfad gegen die registrierten Muster prüfen.
  4. Parameter aus Segmenten wie :id dekodieren.
  5. Ersten passenden Handler ausführen.
  6. Bei popstate erneut auswerten.

API

nj.route(pattern, handler)

nj.route(pattern, handler) → nj

Registriert ein Pfadmuster und einen Handler. Die Reihenfolge ist relevant, da die erste passende Route ausgeführt wird.

nj.route("/", () => {
  nj("#app").html("<h1>Startseite</h1>");
});

nj.route("/projects/:id", ({ id }, path) => {
  console.log(id, path);
});

Der Handler erhält zuerst das Parameterobjekt und anschließend den vollständigen Pfad.

nj.router.start()

nj.router.start() → nj.router

Registriert den internen popstate-Listener und wertet sofort die aktuelle URL aus.

nj.ready(() => {
  nj.router.start();
});
Da jeder Aufruf einen weiteren Listener registriert, sollte start() im normalen Betrieb nur einmal ausgeführt werden.

nj.router.navigate(url, state)

nj.router.navigate(url[, state = {}]) → undefined

Erzeugt mit history.pushState() einen neuen Verlaufseintrag und löst danach künstlich ein popstate-Ereignis aus.

nj.router.navigate("/orders/17", {
  source: "dashboard"
});

// Alias:
nj.navigate("/orders/17");

nj.router.replace(url, state)

nj.router.replace(url[, state = {}]) → undefined

Ersetzt den aktuellen Verlaufseintrag über history.replaceState() und startet anschließend die Routenauswertung.

nj.router.replace("/login", {
  reason: "session-expired"
});

nj.router.params()

nj.router.params() → Object

Wandelt den aktuellen Querystring mit URLSearchParams in ein einfaches Objekt um.

// URL: /search?q=router&page=2
const params = nj.router.params();
// { q: "router", page: "2" }
Alle Werte bleiben Zeichenketten. Mehrfach vorkommende Parameternamen werden durch Object.fromEntries() auf den letzten Wert reduziert.

Routenparameter

Ein Segment mit vorangestelltem Doppelpunkt wird in eine benannte Capture Group umgewandelt.

MusterPassender PfadParameter
/users/:id/users/42{ id: "42" }
/projects/:project/tasks/:task/projects/a/tasks/7{ project: "a", task: "7" }
/tags/:name/tags/Web%20API{ name: "Web API" }

Statische Zeichen im Muster werden nicht zusätzlich escaped. Deshalb sollten Muster einfach gehalten und nicht als frei eingegebene reguläre Ausdrücke behandelt werden.

Praxisbeispiele

Interne Links abfangen

nj(document).on("click", "a[data-route]", event => {
  event.preventDefault();
  nj.navigate(event.currentTarget.getAttribute("href"));
});

Daten je Route laden

nj.route("/users/:id", async ({ id }) => {
  const user = await nj.get(`/api/users/${id}`);
  nj.render("#app", userTemplate, user);
});

Einfacher Fallback

Der Core besitzt keine eigene 404-Route. Eine praktische Lösung ist eine zuletzt registrierte, selbst definierte statische Route oder eine Anwendungsschicht, die vor der Navigation bekannte Pfade prüft.

Filter über Querystring

nj.route("/products", () => {
  const { category, page = "1" } = nj.router.params();
  loadProducts({ category, page: Number(page) });
});

Grenzen des aktuellen Moduls

  • Keine Methode zum Entfernen registrierter Routen.
  • Keine benannte Route und keine URL-Generierung aus Routennamen.
  • Keine Middleware, Guards oder Hooks vor und nach einer Route.
  • Keine Wildcard- oder optionale Parameter-Syntax.
  • Keine eingebaute 404-Behandlung.
  • Keine Methoden back(), forward() oder reload().
  • Keine automatische Behandlung von Link-Klicks.
  • Keine serverseitige Routing-Konfiguration.

Diese Einschränkungen entsprechen dem tatsächlichen Stand von nojquery.core.js.
