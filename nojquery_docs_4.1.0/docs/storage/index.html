Storage

Die Storage-API kapselt localStorage und sessionStorage, serialisiert Werte automatisch als JSON und trennt Daten über Namespaces.

Überblick

nj.storage.local bleibt nach dem Schließen des Browsers erhalten. nj.storage.session gilt nur für die aktuelle Browser-Sitzung beziehungsweise den aktuellen Tab-Kontext.

nj.storage.local.set("theme", "dark");
const theme = nj.storage.local.get("theme", "light");
Standard-Namespace: Beide vorgefertigten Manager verwenden nojquery. Der echte Browser-Schlüssel lautet daher beispielsweise nojquery.theme.

Lokaler Speicher

nj.storage.local

nj.storage.local → StorageManager

Vorkonfigurierter Manager für localStorage.

nj.storage.local.set("language", "de");
console.log(nj.storage.local.get("language"));

Sitzungsspeicher

nj.storage.session

nj.storage.session → StorageManager

Vorkonfigurierter Manager für sessionStorage.

nj.storage.session.set("csrf", token);
const token = nj.storage.session.get("csrf");

Werte speichern

set(name, value)

manager.set(name, value) → value | null

Serialisiert den Wert mit JSON.stringify(). Bei Erfolg wird der ursprüngliche Wert zurückgegeben, bei einem Fehler null.

nj.storage.local.set("user", {
  id: 42,
  name: "Olaf",
  active: true
});

Werte lesen

get(name, fallback)

manager.get(name[, fallback = null]) → any

Liest und dekodiert einen Wert. Fehlt der Schlüssel oder kann er nicht verarbeitet werden, wird der Fallback geliefert.

const settings = nj.storage.local.get("settings", {
  theme: "light",
  language: "de"
});

Existenz prüfen

has(name)

manager.has(name) → Boolean
if (nj.storage.local.has("onboarding")) {
  openDashboard();
}

Eintrag entfernen

remove(name)

manager.remove(name) → Boolean
nj.storage.session.remove("csrf");

Schlüssel auflisten

keys()

manager.keys() → String[]

Liefert ausschließlich Schlüssel des aktuellen Namespaces und entfernt das Präfix aus der Rückgabe.

nj.storage.local.set("theme", "dark");
nj.storage.local.set("language", "de");
console.log(nj.storage.local.keys());
// ["theme", "language"]

Namespace leeren

clear()

manager.clear() → Boolean

Entfernt alle Einträge des Managers, nicht jedoch fremde Browser-Schlüssel anderer Namespaces.

nj.storage.local.clear();

Anzahl der Einträge

size

manager.size → Number
console.log(nj.storage.local.size);

Verfügbarkeit

isAvailable()

manager.isAvailable() → Boolean

Prüft durch temporäres Schreiben und Entfernen, ob der gewählte Browser-Speicher nutzbar ist.

if (!nj.storage.local.isAvailable()) {
  showStorageWarning();
}

nj.storage.available(scope)

nj.storage.available([scope = "local"]) → Boolean
nj.storage.available("session");

Eigene Namespaces

nj.storage.create(scope, namespace)

nj.storage.create([scope = "local"], [namespace = "nojquery"]) → StorageManager

Erzeugt einen unabhängigen Manager. Als Scope wird nur session speziell behandelt; alle anderen Werte führen zu lokalem Speicher.

const auth = nj.storage.create("session", "app.auth");
const settings = nj.storage.create("local", "app.settings");

auth.set("token", token);
settings.set("theme", "dark");

Datentypen

JSON-Serialisierung

TypVerhalten
String, Number, Boolean, nullWerden zuverlässig gespeichert und wiederhergestellt.
Array, ObjectWerden als JSON serialisiert.
DateWird als ISO-String gespeichert und nicht automatisch wieder in ein Date-Objekt umgewandelt.
undefined, Funktionen, SymboleSind keine verlässlichen JSON-Werte und sollten nicht gespeichert werden.
Zirkuläre ObjekteFühren zu einem Serialisierungsfehler; set() liefert dann null.

Fehlerverhalten

Sichere Rückgabewerte

Der Manager fängt Zugriffs-, Quota- und JSON-Fehler ab. Bei aktivem nj.config.debug werden Details in der Konsole ausgegeben.

MethodeFehlerwert
set()null
get()angegebener Fallback
has(), remove(), clear()false
keys()leeres Array

Sicherheit

Browser-Speicher ist nicht geheim

Alle Skripte derselben Origin können auf den Speicher zugreifen. Deshalb dürfen dort keine Passwörter, privaten Schlüssel oder dauerhaft schützenswerten Geheimnisse abgelegt werden. XSS-Schutz bleibt entscheidend.

Tokens: Die Storage-API ermöglicht technisch die Ablage von Tokens, trifft aber keine Sicherheitsentscheidung. Für sensible Authentifizierung sind serverseitige, sichere und HttpOnly-Cookies häufig geeigneter.

Anwendungsmuster

Theme speichern

const settings = nj.storage.create("local", "app.settings");

function setTheme(theme) {
  document.documentElement.dataset.theme = theme;
  settings.set("theme", theme);
}

setTheme(settings.get("theme", "light"));

Formularentwurf

const drafts = nj.storage.create("local", "app.drafts");

nj("#message").on("input", event => {
  drafts.set("contact", event.target.value);
});

nj("#message").val(drafts.get("contact", ""));

CSRF-Wert pro Sitzung

const auth = nj.storage.create("session", "app.auth");
auth.set("csrf", token);

await nj.post("/api/record", payload, {
  headers: { "X-CSRF-Token": auth.get("csrf", "") }
});

Projektbezogener Namespace

const project42 = nj.storage.create("local", "project.42");
project42.set("filters", { status: "open" });
