const result = nj.validate.test(email, {

Überblick

Alle Prüffunktionen liefern true oder false. nj.validate.test(value, rules) kombiniert mehrere Regeln und liefert ein Objekt mit valid und errors.

Wichtig: Das Modul validiert einzelne Werte. Eine automatische Formularanalyse, DOM-Fehleranzeige oder serverseitige Prüfung ist nicht Bestandteil des aktuellen Core.

Direkte Prüffunktionen

nj.validate.required(value)

nj.validate.required(value) → boolean

Lehnt null, undefined, leere Zeichenketten und reine Leerzeichen ab.

nj.validate.required("Olaf"); // true
nj.validate.required("   ");  // false
nj.validate.required(0);      // true

nj.validate.email(value)

nj.validate.email(value) → boolean

Prüft mit einem kompakten regulären Ausdruck auf ein einfaches E-Mail-Format.

nj.validate.email("info@example.org"); // true
nj.validate.email("info@localhost");   // false

nj.validate.url(value)

nj.validate.url(value) → boolean

Verwendet den nativen URL-Konstruktor. Gültig sind Werte, die sich ohne Basis-URL parsen lassen.

nj.validate.url("https://example.org/path"); // true
nj.validate.url("/relative/path");           // false

nj.validate.number(value)

nj.validate.number(value) → boolean

Akzeptiert Werte, die nicht leer sind und sich mit Number() in eine endliche Zahl umwandeln lassen.

nj.validate.number("12.5"); // true
nj.validate.number("");     // false
nj.validate.number("12x");  // false

nj.validate.integer(value)

nj.validate.integer(value) → boolean

Wandelt den Wert mit Number() um und prüft danach Number.isInteger().

nj.validate.integer("42");  // true
nj.validate.integer("4.2"); // false

nj.validate.date(value)

nj.validate.date(value) → boolean

Prüft, ob Date.parse(value) einen gültigen Zeitwert erzeugt.

nj.validate.date("2026-07-23"); // true
nj.validate.date("kein Datum"); // false

nj.validate.phone(value)

nj.validate.phone(value) → boolean

Erwartet mindestens sechs Folgezeichen nach einem führenden Pluszeichen oder einer Ziffer. Erlaubt sind Ziffern, Leerzeichen, Klammern, Punkt, Schrägstrich und Bindestrich.

nj.validate.phone("+49 341 123456"); // true
nj.validate.phone("123");            // false

nj.validate.iban(value)

nj.validate.iban(value) → boolean

Entfernt Leerzeichen, prüft die Grundstruktur und führt anschließend die Modulo-97-Prüfung aus.

nj.validate.iban("DE89 3704 0044 0532 0130 00"); // true

nj.validate.bic(value)

nj.validate.bic(value) → boolean

Prüft einen BIC mit acht oder elf Zeichen nach dem im Core hinterlegten Muster.

nj.validate.bic("COBADEFFXXX"); // true

Grenz- und Längenregeln

RegelSignaturPrüfung

maxmax(value, n)Number(value) <= n

nj.validate.min("18", 18);          // true
nj.validate.max(120, 100);          // false
nj.validate.minLength("abc", 3);    // true
nj.validate.maxLength("abcdef", 5); // false

nj.validate.test()

nj.validate.test(value[, rules = {}]) → { valid, errors }

Durchläuft alle Regeln. Bei true wird die jeweilige Funktion nur mit dem Wert aufgerufen. Bei jedem anderen Argument erhält die Regel zusätzlich diesen Wert.

const result = nj.validate.test("17", {
  required: true,
  integer: true,
  min: 18,
  max: 120
});

// {
//   valid: false,
//   errors: ["min"]
// }
Unbekannte Regeln werden still ignoriert, weil nur vorhandene Funktionen ausgeführt werden. Regelargumente und Fehlermeldungen werden nicht automatisch lokalisiert.

Formularbeispiel

const form = document.querySelector("#registration");

form.addEventListener("submit", event => {
  event.preventDefault();

  const email = form.elements.email.value;
  const age = form.elements.age.value;

  const emailResult = nj.validate.test(email, {
    required: true,
    email: true
  });

  const ageResult = nj.validate.test(age, {
    required: true,
    integer: true,
    min: 18
  });

  if (!emailResult.valid || !ageResult.valid) {
    console.log({
      email: emailResult.errors,
      age: ageResult.errors
    });
    return;
  }

  // Daten erst jetzt an den Server senden.
});

Clientseitige Prüfung verbessert die Bedienung, ersetzt aber keine serverseitige Validierung.

Grenzen des aktuellen Moduls

  • Keine automatische Validierung eines vollständigen Formulars.
  • Keine integrierte DOM-Ausgabe von Fehlermeldungen.
  • Keine benutzerdefinierten Validatoren über eine Registrierungs-API.
  • Keine Regeln wie pattern, equals, between oder custom.
  • Keine asynchronen Prüfungen.
  • Keine Übersetzung oder Zuordnung menschenlesbarer Fehlermeldungen.

Diese Angaben entsprechen der tatsächlich vorhandenen API in nojquery.core.js.
