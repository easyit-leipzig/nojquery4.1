Überblick

Alle drei Funktionen erstellen einen nativen Observer, registrieren sämtliche passenden Ziele und geben die Observer-Instanz zurück. Dadurch bleiben die nativen Methoden wie disconnect(), unobserve() oder takeRecords() verfügbar.

HelferNative GrundlageZweck
nj.observe()MutationObserverDOM-Änderungen beobachten
nj.visible()IntersectionObserverSichtbarkeit im Viewport oder Root prüfen
nj.resize()ResizeObserverGrößenänderungen von Elementen erkennen

nj.observe()

nj.observe(target, callback[, options = { childList: true, subtree: true }]) → MutationObserver

Beobachtet alle passenden Ziele mit einem gemeinsamen MutationObserver. Als Ziel können ein Selektor, ein DOM-Element oder ein NJ-Objekt verwendet werden.

const observer = nj.observe("#messages", (records, obs) => {
  records.forEach(record => {
    console.log(record.type, record.target);
  });
});

Eigene Optionen

const observer = nj.observe(".profile", records => {
  console.log(records);
}, {
  attributes: true,
  attributeFilter: ["class", "data-state"]
});
Standard: Ohne drittes Argument werden Änderungen an direkten und verschachtelten Kindelementen beobachtet. Attribute und Textinhalte sind standardmäßig nicht aktiviert.

nj.visible()

nj.visible(target, callback[, options = {}]) → IntersectionObserver

Registriert alle passenden Elemente bei einem IntersectionObserver. Der Callback wird für jeden Eintrag separat aufgerufen.

callback(isVisible, entry) 
const observer = nj.visible(".section", (isVisible, entry) => {
  entry.target.classList.toggle("is-visible", isVisible);
}, {
  threshold: 0.25
});

Das erste Argument entspricht entry.isIntersecting. Das vollständige native IntersectionObserverEntry-Objekt steht als zweites Argument bereit.

Root-Margin für Vorladen

nj.visible("img[data-src]", (visible, entry) => {
  if (!visible) return;

  entry.target.src = entry.target.dataset.src;
  entry.target.removeAttribute("data-src");
}, {
  rootMargin: "300px 0px"
});

nj.resize()

nj.resize(target, callback) → ResizeObserver

Beobachtet Größenänderungen aller passenden Elemente. Der Callback wird für jeden Eintrag separat aufgerufen.

callback(contentRect, entry) 
const observer = nj.resize(".panel", (rect, entry) => {
  entry.target.dataset.width = Math.round(rect.width);
  entry.target.classList.toggle("compact", rect.width < 480);
});
Der aktuelle Core bietet für nj.resize() kein Optionsargument. Verwendet wird unmittelbar entry.contentRect.

Lebenszyklus und Aufräumen

Da die native Instanz zurückgegeben wird, muss sie bei dynamisch entfernten Komponenten gezielt beendet werden.

const observer = nj.visible(".card", onVisibility);

// alles beenden
observer.disconnect();

Bei Intersection- und Resize-Observern können auch einzelne Elemente abgemeldet werden:

const card = document.querySelector(".card");
observer.unobserve(card);

Bei MutationObservern steht zusätzlich takeRecords() zur Verfügung, um noch nicht ausgelieferte Einträge abzurufen.

Praxisbeispiele

Dynamische Liste zählen

const list = document.querySelector("#tasks");

nj.observe(list, () => {
  nj("#task-count").text(list.children.length);
}, {
  childList: true
});

Animation beim Eintritt

const obs = nj.visible(".reveal", (visible, entry) => {
  if (!visible) return;

  entry.target.classList.add("revealed");
  obs.unobserve(entry.target);
});

Komponentenbreite statt Viewport

nj.resize(".toolbar", (rect, entry) => {
  entry.target.classList.toggle(
    "toolbar--stacked",
    rect.width < 600
  );
});

Mehrere Ziele

const observer = nj.observe(".live-region", records => {
  console.log(records.length);
});

// Ein Observer überwacht alle Treffer.

Grenzen des aktuellen Moduls

  • Keine automatische Fallback-Implementierung für Browser ohne native Observer-Unterstützung.
  • Keine integrierte Debounce- oder Throttle-Option.
  • Keine automatische Abmeldung entfernter Komponenten.
  • nj.visible() gibt nur isIntersecting und den nativen Eintrag weiter, nicht das gesamte Entries-Array.
  • nj.resize() bietet im aktuellen Core kein Optionsargument.
  • Fehler in Callbacks werden nicht intern abgefangen.

Diese Angaben entsprechen der tatsächlich vorhandenen API in nojquery.core.js.
